## 2. Merge / scoring algorithm (concrete)

Data flow: file extractor (EPUB OPF/PDF/CBZ) → candidate search per provider → normalize → score candidates → merge field-by-field with locks → persist.

Normalization: strip ISBN hyphens/spaces, uppercase X, convert ISBN10↔13; trim & NFKC Unicode titles; `publishedDate` → `YYYY`, `YYYY-MM`, `YYYY-MM-DD` all map to a date + `date_precision` enum; languages ISO-639-1/2; descriptions HTML→plain text; dedupe authors case-insensitively.

Candidate score (0–100), adapted from Readest's own `BaseMetadataProvider.calculateConfidence` (readest `apps/readest-app/src/services/metadata/providers/base.ts:51-88`: base 50, +40 exact ISBN, +30×title similarity, +20×author similarity, −20 no cover, +provider bonus):

```
score = 30                                  # base
      + 40 if queried ISBN ∈ normalized candidate ISBNs else -40 if ISBN query and none match
      + 25 * title_similarity               # token-set + Levenshtein, CJK char-bigram ratio
      + 15 * author_similarity
      + 10 if language matches (or both unspecified)
      + 10 if cover present
      + provider_bonus                      # xiaoshuohub 25 for 网文; Google 10; OL/Hardcover 5; file 0
      - 15 per conflicting core field (publisher/year) vs already accepted top candidate
```
Accept only `score ≥ 60` and, if an ISBN was queried, require exact ISBN match (else demote to "weak" and never overwrite locked fields). Query cascade per book: (1) file ISBN13 → Google `q=isbn:` → OL `/api/books?bibkeys=ISBN:` → Hardcover editions → [optional ISBNdb]; (2) ISBN-10 alternate form; (3) `q=intitle:"…"+inauthor:…` with `maxResults=5`; (4) file-extracted metadata as fallback (confidence ~0.4 per GoStack contract). Stop early when a candidate has exact ISBN match + title similarity ≥0.9 + cover.

Field precedence per field (highest first; skip sources where field absent/empty; locked fields always win):
- `isbn13/isbn10`: file EPUB OPF (if checksum-valid) > Google `industryIdentifiers` > Hardcover > OL edition > ISBNdb.
- `title/subtitle/authors`: Google > Hardcover > OL > file > xiaoshuohub (网文 only).
- `publisher/published_date/pages/language`: Google > ISBNdb > Hardcover > OL > file.
- `description`: OL (often richest) > Google (HTML, strip tags) > xiaoshuohub `intro` for 网文 > file.
- `categories/tags`: OL subjects > Google categories > Hardcover > xiaoshuohub (网文 genre + tags).
- `cover_url`: Google `large` > `medium` > xiaoshuohub `cover` (网文) > OL cover by resolved `id`/`olid` (unthrottled) > OL by ISBN (100/IP/5min) > Google thumbnail > extracted embedded cover bytes. Store locally in our own `covers/` dir; do not hotlink Douban (blocked) or proxy OL covers at scale (ToS).
- `rating`: Hardcover aggregate > Google `averageRating` > OL; NEVER Douban scraped rating in default chain (legal).

Lock semantics: `metadata_locks(book_id, field, locked_at)`; per-field user override writes `book_metadata_overrides` and sets lock. Merge writes only unlocked fields; a locked field is never replaced by any provider, including re-scrapes. UI shows provenance per field (`book_field_sources(book_id, field, provider, provider_id, fetched_at, confidence)`) so user can accept/reject suggested values.

## 3. xiaoshuohub integration spec

Source: the public developer documentation at https://www.xiaoshuohub.com/developers/ and the live API at `https://api.xiaoshuohub.com` (probed 2026-11-24: `/v1/search` answers anonymously with `Ratelimit-Limit: 200`).

Auth flow: create an app in the developer portal (`https://api.xiaoshuohub.com/apps/developer/`) with the site account → new app, scope **`default` must be checked** (else token treated as anonymous → IP 200/day) → App Key + Secret server-side only. `POST /authorization/token` with HTTP Basic `APP_KEY:APP_SECRET`, body `grant_type=client_credentials`; response `{access_token, token_type:"bearer", expires_in:172800 (48h), refresh_token, scope:"authorization,default"}`. Refresh via `grant_type=refresh_token&refresh_token=…`. Send `Authorization: Bearer <token>` on every `/v1/*` call.

Quota accounting: 1,000 calls/day per account, **rolling 24 h** (not calendar day), shared across all apps under the account; anonymous 200/day per IP. Every response carries `Ratelimit-Limit` and `Ratelimit-Remaining`; 429 includes `Retry-After` seconds. Errors: `{"error":"…"}`; 400 when page ≥14 (max result index 250), 404 work missing, 502 search unavailable (retry). Implement: persistent token store (refresh at 45 h), local token bucket seeded from `Ratelimit-Remaining`, bounded exponential backoff on `Retry-After`, kill switch when remaining < 50 until reset, and a durable `provider_quota` row so restarts don't overshoot. At 1,000/day, 20k-book library needs ≥20 days for 1 call/book; only query 网文 candidates, never re-fetch unchanged works (`as_of` field enables incremental refresh).

`GET /v1/search`: params `q` (title/author/intro; space-separated phrases), `author` exact, `tags`/`sites` comma-AND, `category` platform-native, `genre` slug (e.g. `xuanhuan`; slug list on the site's `/genre/` pages), `status=ongoing|completed`, `words_min/words_max`, `updated_after=YYYY-MM-DD`, `sort=heat|updated|words` (omit = relevance), `page` from 1, 20 items/page, hard cap 250 results. Response `{total,page,pages,items[{id,title,title_html,author,category,status,word_count,intro_html,sites[],cover}]}`; `*_html` are fully escaped with `<mark>` highlights — strip tags to plain text for our metadata.

`GET /v1/works/{id}`: `{id,title,author,author_id,intro (plain text, \n),cover,genre:{slug,name}|null,category:{site_name,names[]},tags[],tag_pages[],status,word_count,chapter_count,latest_chapter,latest_update (ISO UTC),heat(0–100)|null,rank,top_pct,sources[{site,site_name,url,rating,metrics[{label,value}],heat}],similar[],author_works[],as_of}`.

Field mapping to our Book model:
| Book field | xiaoshuohub source | Note |
|---|---|---|
| title, author | `title`, `author` | plain text |
| description | `intro` | full; search `intro_html` is truncated |
| cover_url | `cover` | download to local cover store |
| tags[] | `tags` + `genre.name` + `category.names[]` | merge, dedupe |
| categories[] | `genre.name` (normalized) | keep raw platform category separately |
| language | — | set `zh` [INFERENCE] |
| word_count, chapter_count | same names | webnovel-specific columns |
| status | `status` | map ongoing→连载中, completed→已完结 |
| latest_chapter, latest_update | same names | webnovel-specific |
| external_id | `id` | store `xiaoshuohub:<id>` as provider_id |
| rating, heat, rank | `sources[].rating`, `heat`, `rank` | store in separate stats table, not canonical rating |
| source_urls | `sources[].url` | provenance |

网文 vs 出版书 discrimination: (a) provider = `xiaoshuohub` ⇒ always 网文 (its works carry **no ISBN and no publisher/publish_date**, only source sites such as Qidian, JJWXC and Shuqi); (b) WeRead `scope=16` results and xiaoshuohub hits are 网文; (c) for any provider, absence of ISBN + presence of word_count/chapter_count/status/ongoing + source site URL ⇒ `work_type=webnovel`; (d) ISBN present ⇒ `work_type=published`. Store `work_type` enum and never cross-merge a 网文 candidate into a published-book record (different identity namespace; only manual user link).

## 4. Go libraries (recommend implement-thin-wrap, not heavy deps)

- **ISBN validation/conversion**: use `github.com/gsiems/go-isbn` (validate/parse/convert, last push 2023-05-01) or `github.com/lukasaron/isbn` (ISO 2108:2017, 2020). Mature; pick one, no network calls.
- **Google Books**: official `google.golang.org/api/books/v1` generated client exists; or tiny custom HTTP client (only 2 GET endpoints + `fields` mask) — prefer custom to avoid dependency bloat. Third-party `eguevara/go-books` (2020) and `onurhunce/go-google-books-client` (2021) are stale.
- **Open Library**: `fakturk/openlibrary-golang-client` (2★, 2022) / `raitucarp/openlibrary-go` (0★, 2026) are immature; implement 6 GET endpoints directly with `fields=` masks.
- **Hardcover**: no credible Go GraphQL client found (GitHub search 2026-11-23); send raw GraphQL JSON POST with `net/http`; strongly typed response structs.
- **Rate limiting**: `golang.org/x/time/rate` (canonical token bucket, verified pkg.go.dev 200) — one limiter per provider; xiaoshuohub also needs daily rolling quota persisted in SQLite.
- **Async jobs**: `github.com/riverqueue/river` (5.9k★, MPL-2.0, v0.51.2 published 2026-11-09, **SQLite support**) fits single-binary and persistent retries; if "low complexity" dominates, a single goroutine worker pool reading a `metadata_jobs` SQLite table (status/attempts/next_run_at) is sufficient — recommend this unless River's operational surface is acceptable. `go-co-op/gocron` (7.2k★, active 2026-11-19) only if periodic refresh scheduling needed.
- **Readest fork**: already has a working provider abstraction worth mirroring in Go: `BaseMetadataProvider` score (`providers/base.ts:51-88`), provider cascade with `Promise.allSettled` sorted by confidence (metadata/service.ts:24-45), GoogleBooksProvider (API key list rotation, `q=isbn:`) and OpenLibraryProvider (`/api/books?bibkeys` then `/search.json`) in `apps/readest-app/src/services/metadata/providers/`. Our server should expose one `POST /api/metadata/search` that returns the same normalized shape so the fork can replace its direct calls via a thin adapter.

## 5. Executive summary (5 lines)
1. Google Books and Open Library remain the practical free ISBN providers, but Google now requires a key (keyless quota = 0, our probe 2026-11-23) with ~1k/day default and observed 100/min/user; OL documents 1–3 req/s and covers 100/IP/5min — 20k books require caching/dumps or a paid tier.
2. Douban's official API is dead since 2018-19 and its remaining endpoints are scraping with explicit 2026 prohibitions: keep it strictly opt-in/user-risk, never default; Hardcover is the only clean licensed GraphQL API (5k/day free, Chinese coverage partial).
3. xiaoshuohub offers exactly two read-only endpoints behind OAuth2 client_credentials, 1,000 calls/rolling 24h per account, 48h tokens, 250-result search cap; it is 网文-only (no ISBN) and maps cleanly to word_count/chapter_count/status/tags/heat fields.
4. Use candidate scoring (ISBN exact-match gate + title/author similarity + provider bonus) and per-field precedence with locked overrides and provenance; never cross-merge 网文 with published books.
5. Implement thin Go HTTP clients + `x/time/rate`; River or a simple SQLite job queue handles async scraping; mirror Readest's existing provider score/cascade shape to minimize client fork work.
