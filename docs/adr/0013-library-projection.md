# 书库投影进每个用户的 Readest 书记录

书库是共享的一份（`library_books`），Readest 的书记录是每个用户一份（`books`）。为了让 Readest 不改数据层、登录即可看到书单，入库时给每个已有用户插入一条书记录，新建用户时把整个书库插进他的书记录；这条记录带 `uploaded_at`，Readest 因此显示"在云端、可下载"。之后书单、阅读状态、进度都写在用户自己的书记录上，按 Readest 的合并规则同步；书库元数据变化时，服务端以新的 `metadata_updated_at` 改写所有用户的元数据字段组，Readest 的字段级时钟会让它覆盖旧值。

Readest 客户端通过 `/api/storage` 上传的书文件，服务端核对内容的书哈希后直接入库成为共享的书；其他对象（字体、纹理、配置附件）按用户存放。管理员在 Readest 里改的元数据写回书库并锁定，普通用户改的只留在自己的书记录里。

## 考虑过的方案

- 拉取时动态合成书记录：省掉存储，但 Readest 的增量游标 `synced_at` 需要每行的真实变更时间，合成的行无法正确分页，也存不下用户自己的书单和阅读状态。
- 只投影给上传者：其他用户看不到书库，违背"登录即看到书单"。

## 后果

- 一万本书、十个用户就是十万行书记录，SQLite 下仍是毫秒级（`research/ScalePerf.md`）。
- 用户在 Readest 里删除书只删除他自己的书记录；从书库删除书（管理员）会给所有用户的书记录打墓碑，批注、进度和阅读统计保留。
