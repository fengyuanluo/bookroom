# 书哈希即身份，书库按内容寻址

一本书就是一个文件，身份是书哈希（partialMD5：从偏移 0 开始，在指数间隔的偏移处各取 1 KiB，共 12 段），与 Readest（`services/bookService.ts:527`）和 KOReader（`util.partialMD5`）的算法一致，三端不用映射就能对上。文件存放在 `library/<哈希前 2 位>/<哈希>/`，入库后不再改动；元数据只存在数据库里，刮削或修改元数据都不重命名、不移动文件。

## 考虑过的方案

- Calibre 式可读路径（`作者/书名/`）：改作者或书名就要移动文件，中文长路径和非法字符需要转义，同名书要额外加 id。
- `books` 与 `book_files` 两张表（Komga、BookLore 的做法，一部作品挂多个格式）：和 Readest 一个文件一个身份的模型冲突。

## 后果

- 不通过数据库就看不出磁盘上的文件是哪本书。
- 同一作品的 EPUB 和 PDF 是两本书。
- 文件字节一改就是一本新书。
- 入库只做一次复制（同盘时用移动或硬链接），读取路径与扫描模式相比没有性能差别；因为服务端是唯一写入方，不需要周期性重扫。
